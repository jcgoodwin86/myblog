 ---
  Project Review — Go Blog (myblog)

  Overall Assessment

  Solid foundation for a blog. The architecture is clean, the caching strategy is correct, and the Templ/Goldmark integration is well-structured.
  Several issues below range from minor style nits to a couple of real bugs worth fixing before publishing.

  ---
  Templ Structure

  What's working well:
  - Clear separation: layout/, components/, pages/ — this is the right split.
  - Data flows cleanly: handlers collect data → pass to page templates → delegate to components. Handlers are thin and do exactly what they should.
  - PostMeta being a templ.Component passed via the extraHead parameter to Layout is a clean pattern — avoids prop-drilling or layout variants.

  Issues:

  templates/components/extrahead.templ — this file defines templ extraHead() (unexported, empty body). It appears to be dead code. Nothing imports or
   calls it. The actual extra-head mechanism works through PostMeta in posts.templ. This file should be deleted.

  // extrahead.templ — nothing calls this
  templ extraHead() {
  }

  postcard.templ:10 — the author link is a dead anchor:
  <a href="#">{ post.Author }</a>
  Either link to an author page or drop the <a> wrapper.

  ---
  Goldmark Pipeline

  What's working well:
  - Goldmark config is fully centralized in internal/render/markdown.go — one place to add/remove extensions.
  - Markdown is not parsed on every request. LoadAllPosts() runs at startup, LoadPost caches on first disk read, and rendered template.HTML is stored
   in the Post struct. This is the right approach.
  - template.HTML is used for the rendered output, so Templ won't double-escape it. templ.Raw() in components/markdown.templ handles it safely.

  Issues:

  Task lists extension is missing — internal/render/markdown.go doesn't include extension.TaskList (GFM). The kitchen-sink post has:
  - [x] Set up project structure
  - [ ] Write actual blog posts
  These will render as plain list items with literal [x] text, not checkboxes. Add extension.TaskList to the extensions list.

  Raw HTML is disabled (Goldmark default) — The kitchen-sink post uses <mark> and <details> HTML passthrough:
  <mark>This text should be highlighted</mark>
  Goldmark strips raw HTML by default (security hardening). These elements will silently disappear. Either remove them from the test post or document
   this as intentional. If you want to enable it (it's your own content), add goldmark.WithParserOptions(parser.WithRawHTML()).

  Chroma style is commented out — render/markdown.go:17:
  // highlighting.WithStyle("catppuccin-latte"),
  Without an explicit style, Chroma falls back to a default. Combined with WithClasses(false) (inline styles), this is functional but the style
  choice is implicit. Either pick a style or document the intent.

  ---
  net/http → Templ → Goldmark Data Flow

  What's working well:
  - LoadAllPosts() at startup with disk-read fallback in LoadPost is a good pattern.
  - sync.RWMutex is used correctly — read lock for lookups, write lock for cache writes.
  - Server has timeouts (ReadTimeout: 5s, WriteTimeout: 10s).
  - Content-Type middleware correctly skips static paths.

  Issues:

  Home page and post page diverge on cache state — GetAllPosts() only returns what's in the cache (populated at startup). LoadPost will also check
  disk on a cache miss, so a new .md file added at runtime would be serveable at /posts/slug but would not appear on the home page. The
  docker-compose comment says "hot-reload posts without rebuilding" — that's misleading. A new post is only surfaced to the home page after a server
  restart.

  LoadAllPosts() is all-or-nothing — main.go:13:
  if err := model.LoadAllPosts(); err != nil {
      log.Fatal(err)
  }
  Any single post with bad frontmatter kills the server at startup. For a personal blog this is probably fine (fail-fast is fine), but it means one
  malformed draft crashes everything.

  TOCTOU race on cache — LoadPost does:
  1. RLock → check cache → RUnlock
  2. (gap here)
  3. Read disk
  4. Lock → write cache → Unlock

  Two concurrent requests for the same uncached slug will both miss step 1 and both read from disk. The result is benign (they write identical data)
  but redundant work happens. golang.org/x/sync/singleflight would prevent this if it ever matters at scale.

  Indentation bug in post.go — internal/handler/post.go:20–27:
  if os.IsNotExist(err) {
      http.NotFound(w, r)
  } else {
      http.Error(w, "Internal Server Error", http.StatusInternalServerError)
  }
      return  // <-- visually looks inside else, actually inside outer if err != nil
  Logically correct (Go doesn't care about indentation for scoping), but misleading. The return should be dedented one level to align with the
  closing } of the inner if/else.

  Hardcoded domain — "https://oddcodeout.io" appears in home.go, about.go, contact.go, and posts.templ. If the domain changes, it's a 4-file edit.
  Should be a package-level constant or pulled from an env var.

  ---
  Markdown Content Files

  What's working well:
  - Frontmatter format is consistent across all three posts: title, date, tags, author, description, optional update.
  - postFromMeta validates all required fields and returns typed errors.
  - Date parsing handles both string and time.Time — the time.Time branch exists because YAML can parse bare dates automatically.

  Issues:

  postFromMeta duplicates date-parsing logic — model/post.go:72–93 and model/post.go:95–113 are nearly identical. The date and update parsing could
  share a helper:
  func parseDateField(v interface{}) (time.Time, error) { ... }

  tags validation is opaque — If tags is omitted vs present but empty, both produce the same error ("tags are required"). The frontmatter YAML for an
   empty list vs missing key behave differently but give the same message.

  post_location naming — Go convention is camelCase for variables, not snake_case. Should be postLocation or a package-level constant.

  Content itself is thin — Both firstpost.md and secondpost.md have Content here... as body. These are clearly placeholders, just noting it for
  completeness.

  ---
  Module Path Mismatch

  go.mod declares:
  module github.com/jcgoodwin/myblog
  The directory is at jcgoodwin86/myblog. The module path doesn't match the actual GitHub username. All internal imports use jcgoodwin/myblog
  consistently so it compiles fine, but if you ever go get this or link to it, the paths won't resolve to the real repo.

  ---
  SEO / Meta

  - Canonical URLs and OpenGraph tags are implemented — good.
  - og:image is commented out in posts.templ:14. Social previews will show no image.
  - Twitter card uses summary (not summary_large_image) — fine, but worth revisiting once there are images.
